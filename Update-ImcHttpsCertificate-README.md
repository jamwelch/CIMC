# Update-ImcHttpsCertificate.ps1

Operator guide for inventorying, generating a CSR for, or importing the **Cisco IMC (CIMC) HTTPS server certificate**. Copy this file into the same folder as `Update-ImcHttpsCertificate.ps1`.

This document is written for someone who may be new to PowerShell and may be working from a **locked-down Virtual Desktop (VDI)** in Visual Studio Code, Windows PowerShell ISE, or Cursor. Every required click and command is spelled out. You do **not** need administrator rights to *run* the script once PowerShell 7.4 and the `Cisco.IMC` module are already present.

## What this script does

It connects to one Cisco IMC, or to every valid row in a CSV of CIMC addresses, and applies **one** method to each host:

| Method | What it does |
| --- | --- |
| `Inventory` (default) | Logs on, reads IMC firmware, reads the **current HTTPS certificate** (CN, issuer, dates). Makes no cert change. |
| `CsrGenerate` (Path A) | Generates a certificate signing request **on that IMC**. The private key stays on the IMC. You take the CSR to your CA, then run `CsrUpload`. |
| `CsrUpload` (Path A) | Uploads the CA-signed **server** certificate that was minted from **that IMC’s** CSR. |
| `ExternalImport` (Path B) | Uploads an existing certificate **and** matching private key, then activates them. Same pair can be used on many IMCs. **Requires IMC firmware 4.1.2 or later.** |

Fleet floor for this script: **IMC 4.0.4 or newer**.

- **4.0.4 through 4.1.1:** Path A only (`CsrGenerate` / `CsrUpload`). Path B is refused.
- **4.1.2 and later:** Path A or Path B.
- **Older than 4.0.4:** that host is skipped unless you pass `-ContinueOnOldFirmware` (Path A only; Path B is still refused below 4.1.2).

### What this script does **not** do

It updates **only** the CIMC **HTTPS server** certificate (the one browsers, HTML5 KVM, the XML API, and Redfish HTTPS use).

It does **not** rotate or replace:

- KMIP client certificates, keys, or KMIP root CAs (SED / remote key management)
- LDAP CA certificates
- mTLS client CAs
- SPDM / MCTP endpoint CAs
- Secure Boot or rsyslog CAs
- UCS Manager fabric-interconnect HTTPS
- Intersight Device Connector certificates

IPMI over LAN does **not** use this certificate. HTML5 KVM and virtual media **do** (they drop when HTTPS restarts).

It also does **not**:

- Convert PKCS #12 (`.p12` / `.pfx`) to PEM — convert on the workstation **before** you run the script
- Embed or print certificate or private-key bytes
- Store passwords in the script, CSV, report, or log
- Push the issuing CA into anyone’s browser trust store (you still need that separately)

## 5. Credentials (never in a file)

When you omit `-Credential`, the script calls **`Get-Credential` once** at the start:

- Window title/message: CIMC **admin** login.
- Username: your IMC admin user (often `admin`).
- Password: typed in the prompt. It is stored as a `PSCredential` **in memory for this run only**.

That credential is **reused** for every CIMC in the CSV, including reconnect after a certificate change.

If login **fails** for a host:

1. The script logs the failure **without** the password.
2. It prompts again and **names the CIMC address** that failed.
3. After a successful retry, it asks whether to use the replacement credential for **remaining** hosts in this run (`Y` / `N`).

Passwords are **never** written to the report, the sidecar `.log`, the CSV, or the `.ps1`. Do not put passwords in the CSV. Do not use `ConvertTo-SecureString -AsPlainText`. Do not pass a password as plain text on the command line.

If you use a remote SCP/SFTP share, a **second** `Get-Credential` prompt asks for the **share** login (not the IMC login).

## CSV format

If you pass **both** `-CsvPath` and `-ImcAddress`, **the CSV wins**. `-ImcAddress` is ignored with a warning.

### Address column (required)

Each data row needs a CIMC IPv4/IPv6 address or FQDN in **one** of these headers (first non-empty match wins):

`ImcAddress`, `Address`, `IP`, `IPv4`, `CIMC`, `CimcAddress`, `Host`, `Name`

Recommended header: **`ImcAddress`**.

If the address cell is empty, the script may use `Hostname` / `FQDN` when that value itself looks like an IP or FQDN.

Empty rows and invalid addresses are **Skipped** and recorded in the report. The run continues with the next row.

### Optional columns

| Column | Purpose |
| --- | --- |
| `Hostname`, `FQDN`, `DnsName` | Label in the report; used as ExpectedName if that column is empty. |
| `ExpectedName` | Name browsers will use; compared to cert CN/SAN during openssl preflight. |
| `CertificatePath` or `CertPath` | Per-row PEM/CRT/CER path (overrides `-CertificatePath` for that host). |
| `PrivateKeyPath` or `KeyPath` | Per-row PEM key path (overrides `-PrivateKeyPath` for that host). |

The **same** `-Method` is applied to every valid row. Per-row paths and ExpectedName override the script parameters for that host only.

## How to run (copy these after `Set-Location`)

Use **`pwsh -File`**, not `powershell.exe -File`.

Optional: read the built-in help.

```powershell
Get-Help .\Update-ImcHttpsCertificate.ps1 -Full
```

### Inventory (safe first run)

Single host:

```powershell
pwsh -File .\Update-ImcHttpsCertificate.ps1 -ImcAddress 192.0.2.10 -Method Inventory
```

CSV:

```powershell
pwsh -File .\Update-ImcHttpsCertificate.ps1 -CsvPath .\cimc-lab.csv -Method Inventory
```

A credential dialog appears. After the run, check the report CSV and `.log` in the current folder.

### Path A — generate a CSR (`CsrGenerate`)

IMC time/NTP must be correct **before** you generate a CSR.

`-CountryCode` is the **full country name** from Cisco IMC’s list (for example `United States`), not a two-letter ISO code. Do not use `&` in Common Name or Organizational Unit. SAN limit: **10** entries total (`DNS:`, `IP:`, `EMAIL:`, `URI:`). Default signature algorithm is **sha384**. SHA-1 and MD5 are refused.

```powershell
pwsh -File .\Update-ImcHttpsCertificate.ps1 -CsvPath .\cimc-lab.csv -Method CsrGenerate -CommonName imc-lab-01.example.com -Organization 'Example Inc' -OrganizationalUnit Lab -Locality 'San Jose' -State California -CountryCode 'United States' -SubjectAlternativeName 'DNS:imc-lab-01.example.com','IP:192.0.2.10' -RemoteServer 192.0.2.20 -RemoteFile /certs/imc-lab-01.csr -RemoteProtocol scp
```

If you omit `-RemoteServer` / `-RemoteFile`, the CSR is generated on the IMC and is **not** printed by this script. Copy it from the IMC GUI or CLI, submit it to your CA as a **server** certificate, then run `CsrUpload`.

### Path A — upload the CA-signed cert (`CsrUpload`)

The file must be the cert minted from **that IMC’s** CSR (PEM / CRT / CER).

```powershell
pwsh -File .\Update-ImcHttpsCertificate.ps1 -ImcAddress 192.0.2.10 -Method CsrUpload -CertificatePath C:\certs\imc-lab-01.cer -ExpectedName imc-lab-01.example.com
```

HTTPS and SSH will drop. The script waits (default **90 seconds**), reconnects, and reads the current certificate.

### Path B — import existing cert + key (`ExternalImport`)

Firmware **4.1.2+** only. Local paths for openssl preflight plus upload, **or** an IMC-reachable SCP/SFTP share (`-RemoteServer`, `-RemoteCertificateFile`, `-RemotePrivateKeyFile`) with local paths still used for preflight.

```powershell
pwsh -File .\Update-ImcHttpsCertificate.ps1 -CsvPath .\cimc-lab.csv -Method ExternalImport -CertificatePath C:\certs\wildcard.pem -PrivateKeyPath C:\certs\wildcard.key -ExpectedName imc.example.com
```

### Preview without changing a certificate (`-WhatIf`)

Supported. Inventory still connects and reads; upload/generate/activate steps are skipped.

```powershell
pwsh -File .\Update-ImcHttpsCertificate.ps1 -CsvPath .\cimc-lab.csv -Method ExternalImport -CertificatePath C:\certs\wildcard.pem -PrivateKeyPath C:\certs\wildcard.key -ExpectedName imc.example.com -WhatIf
```

```powershell
pwsh -File .\Update-ImcHttpsCertificate.ps1 -ImcAddress 192.0.2.10 -Method CsrUpload -CertificatePath C:\certs\imc-lab-01.cer -WhatIf
```

A failed host does **not** stop the CSV loop unless you pass `-ErrorAction Stop`.

## After a certificate change: HTTPS and SSH drop

When `CsrUpload` finishes, or when Path B **activates**, Cisco IMC disconnects **HTTPS and SSH** sessions (management-plane restart). The **host operating system typically stays up**.

| Session | Expected |
| --- | --- |
| IMC HTTPS GUI, XML API, Redfish HTTPS | Drop; reconnect after about a minute |
| SSH to CIMC | Drop |
| HTML5 KVM / virtual media | Drop (they use HTTPS) |
| Serial console / SoL | **Keep this available** for recovery |
| IPMI over LAN | Does not use this certificate |

The script waits (`-ReconnectWaitSeconds`, default 90), reconnects with the in-memory credential, and calls `Receive-ImcCertificate`. If HTTPS stays down, recover from **CIMC CLI or serial**.

**Browser trust is separate.** Clients still need the **issuing CA** in their trust store. PowerTool connecting with an ignored invalid cert is **not** proof that a browser will trust the new certificate.

## openssl preflight (workstation, before upload)

For `CsrUpload` and `ExternalImport`, the script runs `openssl x509` against the **file path** you supplied (unless `-SkipCertificatePreflight`, which is not recommended).

It refuses:

- Expired certificates
- SHA-1 or MD5 signatures
- RSA keys smaller than 2048 bits
- Elliptic curves weaker than P-256 (for example P-192 / P-224)

It warns if the certificate is **not yet valid** or is **self-signed**. It compares CN/SAN to `-ExpectedName` (or the CSV hostname). For Path B it also checks that the private key file looks like an unencrypted PEM and that the key matches the leaf certificate. **PEM bytes are never printed** and never written to the report.

You can inspect a file yourself (replace the path):

```text
openssl x509 -text -noout -in C:\certs\wildcard.pem
```

If `openssl` is not on `PATH`, preflight fails and the script stops that upload. Ask IT to provide OpenSSL, or install it only if VDI policy allows. The script does not install OpenSSL. Skipping preflight can install an expired or weak certificate and take HTTPS down.

## Security notes

- **No hardcoded secrets.** There are no passwords, API keys, or PEM blocks in the script. Do not add any.
- Cert and key material is read from **operator-supplied paths** at runtime only.
- Remote share passwords are passed to PowerTool for that cmdlet call only and are not logged.
- Prefer **SCP or SFTP**. TFTP/FTP/HTTP are not offered by this script; private keys must not travel on those protocols.
- Treat `.ps1` files as public once they are in Git. Keep keys and CSVs with real IPs out of public copies if that is your policy; sample CSVs in this README use documentation addresses only.
